# MazMazRadio

online radio streaming

## Откуда берутся станции

В плейлисте только живые потоки — каждый проверен (200 `audio/*`, валидный TLS).
Снятые как мёртвые с причинами — в [`docs/dead-streams.md`](docs/dead-streams.md).

Два слоя, каждый правится в одном месте:

| Что | Где |
|---|---|
| **Источник** — плейлист: URL потоков, названия, `group-title` | `app/src/main/assets/playlists/hostingradio.m3u` |
| **Категории** — метки групп и порядок аккордеонов | `app/src/main/java/.../data/Categories.kt` |

`M3uParser` берёт название из строки `#EXTINF` (всё после запятой, закрывающего блок
атрибутов) и категорию из `group-title`; без `group-title` → `Categories.DEFAULT`
(`Разное`). Названия и категории нигде больше не переопределяются: что в m3u, то и в UI.
Эмодзи в названиях категорий нет — только текст.

`AppConfig.PRESET_PLAYLISTS` (`data/AppConfig.kt`) перечисляет источники: путь вида
`file:///android_asset/...` читается из assets, `http(s)://…` — скачивается. Можно
добавить второй пресет, станции склеятся.

### Добавить / убрать станцию

Плейлист правится руками — `#EXTINF` + строка с URL, внутри секции в том порядке,
в котором станции должны показываться. Новая категория = новая константа в `Categories`
(и в `ORDER`, иначе уедет в конец списка). Потом:

```bash
./gradlew testDebugUnitTest     # плейлист парсится, категории бьются с Categories
./gradlew checkPlaylist         # все потоки отвечают (нужна сеть; 8 потоков параллельно)
```

`checkPlaylist` — это `tools/check_streams.sh`: обходит все `#EXTINF` из плейлиста,
качает первые байты каждого потока и печатает `ok` / `DEAD` с кодом и `Content-Type`.
Live-поток не заканчивается, поэтому обрыв по таймауту (`curl` exit 28) с `200 audio/*`
— это «живой», а не ошибка. В обычные тесты проверка не встроена: ей нужен интернет.

В `docs/dead-streams.md` лежит список убранных как мёртвые потоков с причинами —
оттуда видно, что и почему убрано и что вернуть, если поток оживёт (часть из них
продублирована как регресс в `PlaylistTest`).

## Как ведёт себя воспроизведение

| Ситуация | Что происходит |
|---|---|
| Поток упал / пропала сеть | `RadioService` переподключается сам через 1s, 2s, 4s; если не помогло — снэкбар с причиной и кнопкой «Повторить» (ручная попытка счётчик автоповтора не тратит) |
| Пользователь нажал паузу | автоповтор не срабатывает: `playWhenReady == false` |
| Свайп задачи на паузе | сервис останавливается (`RadioService.onTaskRemoved`); если эфир играет — продолжает и остаётся управляемым |
| Первый запуск эфира на Android 13+ | запрашивается `POST_NOTIFICATIONS`, иначе система не покажет уведомление с кнопками |
| Холодный старт | вспоминается последняя станция, но поток не буферизуется до нажатия play |
| Таймер сна | живёт в процессе (`service/SleepTimer`), а не во ViewModel: свайп приложения его не сбрасывает; считается от дедлайна, поэтому не уезжает |

Избранное и «последняя станция» хранятся по ключу станции (`data/StationKey`), а не по
сырому URL: смена схемы, токена в query или порта по умолчанию не обнуляет сохранённое.
Старые записи мигрируются при первом чтении.

### Картинки станций

В плейлисте нет `tvg-logo`, поэтому вместо обложек рисуется нейтральная круглая плашка
с мотивом приложения (`ui/StationLogo.kt`). Захотите реальные логотипы — вернуть
`tvg-logo` в `#EXTINF`, `logoUrl` в `RadioStation`, загрузку картинки (Coil) и
`logoUrl` в вызовах `StationLogo`.

### HLS

Часть потоков (DFM, тематические каналы Дорожного радио) отдаёт HLS
(`…/playlist.m3u8`) — `media3-exoplayer-hls` уже в зависимостях, отдельной ветки в коде не нужно.
